# Decision Log — Guitar App PRD

| # | Date | Decision | Rationale | Alternatives Considered |
|---|------|----------|-----------|------------------------|
| 1 | 2026-05-22 | 5–7 predefined Free Tunings; remaining predefined + Custom Tunings = Premium | Creates a clear, graduated paywall — free users get enough to try the app, premium unlocks the full range | All predefined tunings free (weakens paywall), only custom tunings paywalled (not enough hook) |
| 2 | 2026-05-22 | Freeform Marking + Select-to-Highlight both supported | Builder explicitly requested both modes | Select-only (simpler but loses freeform exploration) |
| 3 | 2026-05-22 | Note names as a toggle, off by default | Builder wants clean UI; toggle preserves optionality without clutter | Always visible (cluttered), omit entirely (loses utility) |
| 4 | 2026-05-22 | Annual subscription only (no monthly) | Simpler billing; competitive positioning below UG/Chordify | Monthly + annual (added complexity for v1) |
| 5 | 2026-05-22 | Chord progressions = Premium | Grouped with other power-user Premium features | Free (undercuts paywall value) |
| 6 | 2026-05-22 | Capo support = Free Tier | Basic fretboard utility, not a premium differentiator | Paywalled (would feel punitive) |
| 7 | 2026-05-22 | ~5 preview items in each library | Enough to demonstrate value; not so many it removes incentive to subscribe | 3 (too few), 10 (too generous) |
| 8 | 2026-05-22 | Web app only in v1, mobile-responsive | Simplest path to launch; covers mobile without native app overhead | Native mobile (v2 consideration) |
| 9 | 2026-05-22 | React frontend + Java + Maven backend | Builder's stated stack preference | — |
| 10 | 2026-05-22 | Audio playback = Non-goal for v1 | Scope control; visual reference is the core value prop | Include audio (significant added complexity) |
| 11 | 2026-05-22 | Subscription price = $12/yr | Builder's stated target; meaningfully below UG ($40) and Chordify ($60) | Higher price (less competitive), lower (unsustainable) |
| 12 | 2026-05-22 | Google OAuth + email/password auth | Confirmed by builder; Google OAuth as primary, email as fallback | Google OAuth only (excludes some users), email only (higher friction) |
| 13 | 2026-05-22 | Fretboard state saved between sessions for authenticated users | Confirmed by builder; improves UX for returning players | No persistence (annoying to re-configure on every visit) |
| 14 | 2026-05-22 | 6-string only in v1 | Confirmed by builder; simplifies data model significantly | 7-string support (v2 consideration) |
| 15 | 2026-05-22 | Payment processor must support SA bank accounts; PayFast recommended | Builder based in South Africa; PayFast is SA-native with ZAR support and simpler local onboarding than Stripe SA | Stripe SA (works but more friction for local accounts), PayGate/Peach Payments (alternatives, less commonly used) |
| 16 | 2026-05-22 | Tuning dataset compiled comprehensively from public sources | Builder wants every named tuning available; free/premium split applied on top of the full dataset | Manually curating a limited set (labour intensive and incomplete) |
