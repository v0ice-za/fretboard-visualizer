Guitar App — Design Directions

Direction A — Persistent Top Control Bar Recommended

Single 48px control bar at the top. Tuning, key, and scale selectors always visible. Mode chips row appears below when a scale is active. Fretboard fills all remaining height. Closest to the Songsterr pattern — content dominant, chrome minimal.

Strengths

  • Fretboard gets maximum vertical height — nothing competes
  • Core controls always visible without any navigation
  • Mode chips appear only when relevant (progressive disclosure)
  • Scales with the viewport naturally on any screen size
  • Familiar pattern — matches how Songsterr and most web tools work
  • Easy to extend the control bar for future features

Tradeoffs

  • 80px of vertical space used by bars when mode row is visible
  • Library access requires a separate panel/drawer trigger

Direction B — Left Side Panel

All controls in a compact vertical left panel. Fretboard occupies the full right portion. Good for users who want all controls at a glance without scrolling. Can feel cramped if the library is also surfaced here.

Direction C — Bottom Control Bar

Controls live at the bottom, DAW/transport-style. Fretboard fills the full upper portion of the viewport — maximum visual space for the neck. The controls feel like a transport bar under the fretboard content.

Strengths

  • Fretboard gets the most vertical height of any direction
  • Feels like a professional DAW transport — familiar to music software users
  • Mode chips and core selectors on the same row — very compact

Tradeoffs

  • Controls at the bottom can feel counterintuitive for a web app
  • Bottom bar gets crowded with 7 mode chips + 3 selectors at once
  • Eye travels far from fretboard to controls and back

Direction D — Floating HUD

Fretboard fills the entire viewport. Controls float as a glassmorphism HUD overlay at the top, minimisable. Maximum immersion — the neck is all you see. Great for focus mode, but adds discoverability friction for new users.

Strengths

  • Maximum fretboard real estate — full screen, edge to edge
  • Glassmorphism HUD feels premium and modern
  • Minimisable — power users can hide the UI entirely
  • Great for a "focus mode" or presentation view

Tradeoffs

  • HUD can obscure fretboard dots near the top frets
  • Discoverability is lower — new users may not find all controls
  • More complex to implement correctly (z-index, blur, interaction states)
  • Mobile doesn't benefit — HUD doesn't make sense at 375px

Direction E — Split View with Integrated Library

Left panel shows controls + the full scale/chord library inline. Right panel is the fretboard. The library is always accessible without a drawer or modal. Good for exploration-heavy sessions.

Strengths

  • Library always visible — great for browsing scales and chords
  • Paywall states visible inline without a modal
  • Good for the 60/40 scale-to-chord exploration workflow

Tradeoffs

  • Fretboard width significantly reduced — neck feels narrower
  • Panel takes 220px that could be fretboard real estate

Direction F — Minimal Top Bar + Library Drawer

The slimmest possible top bar with only the three core controls. Library is hidden until needed — accessed via a "Library" button that slides a panel up from the bottom. Best balance of fretboard space and access to library content.
