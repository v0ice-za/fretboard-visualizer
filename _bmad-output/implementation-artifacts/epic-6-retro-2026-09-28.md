## Challenges & Patterns

### Pattern 1 — Review-agent false-positive rate was high this epic
5/5 Blind Hunter findings on 6.1 were false positives (agent worked from a truncated diff). On the 6.2+6.3 combined review, 3/4 findings were false positives after verifying against real source (a CSS scroll-behavior misunderstanding, a test that already existed, and an established pattern flagged as "scope creep"). **Lesson: always verify review findings against actual source/tests before triaging as real — do not apply a "patch" on an agent's word alone.**

### Pattern 2 — Acceptance criteria compliance ≠ user satisfaction
Epic 5's Aurora glass-first UI overhaul (5 stories, all done, all reviewed, WCAG contrast audits passed) still did not land with the project owner on look/feel. Every code-review gate that could be automated (contrast ratios, glass-utility consistency, tap targets) passed — but none of those measure whether the result feels "premium" or "uncluttered" to the person who owns the product. **No live look-and-decide checkpoint with the owner happened mid-epic.**

### Pattern 3 — A real, unnoticed layout regression was compounding for 3+ epics
Live-driving the app during this retrospective (not just running vitest) surfaced a genuine CSS bug: opening the Library panel clips the mode-selector row into a disconnected floating horizontal-scroll strip, and the panel itself doesn't render full-height as its own code specifies (`glass-surface hidden flex-col md:flex` on a grid area meant to span the viewport). This bug predates Epic 6 and got worse as tabs were added (6.1's Diatonic, 6.3's Jazzify) — each new tab compounded the existing clutter rather than being caught against a clean baseline. Additionally, `PaywallCard` renders directly on top of the tab that triggered it, no backdrop — reads as broken, not as an upsell moment. **These are functional bugs, not subjective taste, and they were invisible to the automated test suite the whole time.**

### Pattern 4 — No way to fully test premium features as the owner
The owner cannot currently access premium-gated functionality for testing without a real Stripe subscription or manually-seeded premium account, which has been slowing down the ability to evaluate the full app (Progression, Jazzify, premium themes, expanded chord library all locked from casual testing).

### Resolution detail (items 1–5)

**Root cause found for 2/3/4**: `.app-shell`'s CSS Grid (`index.css`) defines named `grid-template-areas` (`top-bar`, `mode-row`, `fretboard`, `library-panel`, `bottom-bar`), but `ControlBar`, `ModeChipsRow`, `<main>`, and `<footer>` in `App.jsx` were never assigned a `grid-area` — only the fretboard div and the library `<aside>` were. Every other element fell through to CSS Grid's implicit auto-placement, which (on the 2-column desktop layout) silently packed `ModeChipsRow` into the narrow 320px library column and pushed `main`/`footer` into the wrong row entirely. This was invisible to the Vitest suite (jsdom doesn't lay out CSS Grid) and coincidentally harmless on the single-column mobile layout, which is why it went unnoticed since whenever the Aurora grid system was introduced in Epic 5.

**Fix**: explicit `style={{ gridArea: ... }}` added to all four elements in `App.jsx`; removed ~60 lines of dead pre-Aurora flexbox CSS from `App.css` (`.app-top-bar`, `.app-header*`, `.app-logo/title/subtitle`, `.app-section` — confirmed unreferenced anywhere in JSX).

**Item 5**: added a non-interactive dimming scrim behind `PaywallCard`'s floating popover, matching the existing `SheetOverlay` convention (`bg-black/10` + `backdrop-blur-xs`), so it now reads as an intentional upsell moment.

**Item 1**: `useSubscription.ts` gates the override on `import.meta.env.MODE === 'development'` (not `.DEV`, which Vitest also sets `true` in test runs and would have let `.env.local` leak into the test suite — caught and fixed during this session, 3 tests failed then passed after the correction). Verified zero occurrences of the flag in the production bundle via `grep` after `pnpm build`.

**Regression**: 523/523 frontend tests, `tsc`/`eslint`/`vite build` all clean. Live-verified in Chrome: Library panel full-height, mode row intact, Jazzify/Progression/Chords/Diatonic tabs all functional and unlocked via the dev flag, footer no longer floating.

## Process Agreement Going Forward
- Re-verify code-review agent findings against real source/tests before applying any patch (Pattern 1)
- Any future UI/UX-heavy epic gets at least one live look-and-decide checkpoint with the project owner mid-epic, not just at the end (Pattern 2)
- Run a live browser check (not just vitest) at the end of any epic that touches shared layout/chrome components, since compounding layout bugs are invisible to unit tests (Pattern 3)
